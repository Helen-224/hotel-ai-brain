# Hotel AI Brain 0.4.2.2
# 任务执行与跨部门协调 PRD

版本：0.4.2.2

产品：Hotel AI Brain · 酒店智能运营大脑

## 1. 产品目标

在 0.4.2.1 协调方案应用机制的基础上，建立业务任务的实际模拟执行流程。

让工作人员能够根据当前有效安排执行任务，让管理人员能够从运营协调中心追踪任务进度、查看部门执行情况、发现阻塞并处理执行异常。

核心价值：

让 AI 协调方案从资源安排进一步进入实际工作执行。

## 2. 用户角色

### 管理人员

- 查看酒店整体执行态势。
- 查看跨部门任务进度。
- 查看任务负责人和支援安排。
- 查看任务阻塞原因。
- 接收执行异常。
- 处理需要管理决策的问题。
- 必要时发起重新协调。

### 工作人员

- 查看分配给自己的任务。
- 查看任务详情及关联业务记录。
- 查看前置任务。
- 开始执行任务。
- 提交任务完成反馈。
- 报告执行异常。

本阶段使用模拟员工身份，不建设真实账号及权限系统。

### AI 协调能力

- 检查任务前置条件。
- 识别执行阻塞。
- 汇总跨部门进度。
- 发现执行异常。
- 向管理人员提供协调依据。

## 3. 核心执行流程

协调方案应用 → 任务执行视图 → 工作人员接收任务 → 开始执行 → 完成或报告异常 → 管理人员追踪 → 形成执行记录。

## 4. 任务状态

保留现有 BusinessTask.executionStatus：

- pending：待执行
- in_progress：进行中
- completed：已完成

受阻状态根据前置任务、维修阻塞及开放异常动态派生，不新增独立执行状态。

verificationStatus 保持独立，不在本阶段自动修改。

## 5. 任务执行规则

### 开始任务

必须满足：

- 任务存在。
- 任务当前处于待执行状态。
- 操作员工是当前任务负责人。
- 相关授权及执行计划条件满足。
- 所有前置任务已经完成。
- 维修阻塞条件已经解除。
- 不存在阻止任务启动的业务约束。

不满足条件时禁止启动，并展示具体原因。

### 完成任务

必须满足：

- 任务当前处于进行中。
- 操作员工是当前任务负责人。

完成后：

- executionStatus 更新为 completed。
- 追加完成操作记录。
- 保存执行人员和完成时间。
- 同步所有引用该任务的事件。
- 更新关联执行计划进度。

不自动完成业务结果验证。

### 执行异常

支持：

- 任务延迟。
- 人员不可用。
- 业务条件变化。
- 执行过程中发现新问题。

报告异常后：

- 保存异常类型和说明。
- 保存报告人和时间。
- 通知管理人员视图。
- 不自动修改任务负责人、时间或执行状态。
- 不自动重新分配资源。

重新调整资源必须重新经过协调方案流程。

## 6. 任务依赖

保留现有房间级依赖关系：

维修执行 → 清洁 → 检查 → 前厅交付确认。

每个房间独立判断。

不将全部客房任务设置为全局串行。

独立的前厅需求核对和其他可以提前开展的任务允许并行执行。

必须继续使用现有：

- dependsOnTaskIds
- blockedByMaintenanceOrderIds

不得绕过现有维修和任务依赖检查。

## 7. 执行操作记录

新增 TaskExecutionRecord：

- recordId
- taskId
- eventId
- executionPlanId
- action
- actorEmployeeId
- occurredAt
- note

记录任务开始、完成和异常报告等操作。

记录不可替代当前任务状态。

## 8. 执行异常记录

新增 TaskExecutionException：

- exceptionId
- taskId
- eventId
- executionPlanId
- reportedBy
- exceptionType
- description
- status
- createdAt

异常状态用于管理人员跟进，不自动改变任务执行状态。

## 9. 页面结构

继续使用运营协调中心，不新建独立业务页面。

主要修改现有执行追踪 Tab。

### A. 协调执行态势

展示：

- 待执行数量。
- 进行中数量。
- 已完成数量。
- 受阻任务数量。
- 待处理异常数量。

所有数字由当前业务状态派生。

### B. 跨部门任务执行

按部门组织任务：

- 工程部。
- 客房部。
- 前厅部。
- 餐饮部。

展示负责人、计划时间、任务状态、前置条件和异常。

支持展开查看任务详情。

### C. 工作人员执行视图

支持模拟员工身份切换。

工作人员只看到分配给自己的任务，并可以：

- 查看任务。
- 开始执行。
- 完成任务。
- 报告异常。

不建设独立员工系统。

### D. 管理人员异常处理

展示异常类型、报告人、关联任务、影响部门及说明。

支持管理人员查看和跟进。

不得直接修改获批方案的安排；需要调整资源时重新进入协调方案流程。

## 10. 状态管理

继续以 Platform.tsx 为统一业务状态管理入口。

任务执行状态沿用现有事件任务转换机制。

新增执行记录和异常记录。

所有引用同一 BusinessTask ID 的事件必须同步状态。

ExecutionPlan 的执行进度由 affectedTaskIds 对应的当前任务状态派生，不重复存储任务状态。

跨页面切换保留状态，刷新后按现有 Demo 规则重置。

## 11. 技术约束

- React 19。
- TypeScript 7 strict。
- Vite 8。
- 原生 CSS。
- 不引入新依赖。
- 不引入真实数据库。
- 不引入后端。
- 保留 0.4.2.1 当前安排覆盖机制。
- 保留原始模拟种子数据。
- 不重复创建业务任务。

## 12. 本阶段禁止实现

- 自动业务结果验证。
- 自动维修验证。
- 自动修改客房就绪状态。
- 自动完成客房交付。
- 自动解决运营事件。
- AI 自主重新分配人员。
- 未经审批的资源调整。
- 真实员工登录和权限。
- 新的数据库和后端。

## 13. 验收标准

1. 已应用方案中的任务能够进入执行流程。
2. 工作人员只能操作当前分配给自己的任务。
3. 待执行任务可以开始。
4. 进行中任务可以完成。
5. 重复开始和重复完成受到保护。
6. 前置任务未完成时禁止启动后续任务。
7. 维修阻塞规则保持有效。
8. 独立任务可以并行执行。
9. 跨事件共享任务状态同步。
10. 每次执行操作都有操作人和时间记录。
11. 异常能够记录并展示给管理人员。
12. 报告异常不自动修改业务安排。
13. 管理人员可以查看跨部门执行进度。
14. 执行计划进度与真实任务状态一致。
15. 任务完成不自动改变 verificationStatus。
16. 任务完成不自动修改房态。
17. 任务完成不自动解决事件。
18. 0.4.2.1 方案应用、支援占用和重复应用防护正常。
19. 原有 3B-1.1、3B-2、3B-3.1 逻辑不回归。
20. 生产构建、业务断言和独立浏览器交互验收通过。

完成后停止，等待产品验收。
